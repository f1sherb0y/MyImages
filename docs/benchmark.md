# 实测

2026-11-12，在开发用的这台机器上（Windows 11 26300，Go 1.27.3）。和 ImageGlass 10.0.906（Store 版）比，两边都是热启动（各自先跑过），同一张图、同一把秒表。

## 结果

| | MyImages 0.1.0 | ImageGlass 10 |
|---|---:|---:|
| 打开一张 4896×6528 的 JPEG（7.3 MB），到图出现在窗口里 | **162–178 ms** | 717–736 ms |
| 同一文件夹里按 → 到下一张（1181 张手机照片） | **25 ms** | 528–552 ms |
| 打开一张 2448×3264 的 PNG（11 MB） | **191 ms** | 761 ms |
| 同一文件夹里按 → 到下一张（PNG、TIFF、WebP、BMP 混合） | **25 ms** | 81 ms |
| 显示那张 JPEG 5 秒后的内存（工作集 / 私有） | **138 / 193 MB** | 1293 / 1475 MB |
| 到显示出来用掉的 CPU 时间 | 0.83 s | 2.5 s |
| 之后空闲 5 秒的 CPU 时间 | 0.03 s | 0.03 s |
| 磁盘 | exe 21 MB，安装包 8 MB | 安装后 107 MB |

数字是中位数：打开各 7 次，切换各 42 次（PNG 那组 ImageGlass 是 28 次）。MyImages 切换的 42 次里有一次是 726 ms，其余都在 19–38 ms；没有查到那一次的原因。

「打开」包括进程启动。MyImages 自己打的时间戳（`MYIMAGES_TRACE=1`）：进程开始后 14 ms 界面循环就绪，约 50 ms 窗口建好，约 70 ms 第一张图解码完，约 115 ms 第一帧画出（在内存里画，不等显卡驱动加载），余下是系统把窗口显示出来。

## 测法

`tools/startbench` 是一把从外面看的秒表，对哪个看图软件都一样：

- 启动程序并带上图片路径，然后每毫秒找一次标题里有这个文件名的可见窗口，用 `PrintWindow` 读窗口中间 96×96 像素；这块像素不再是单色背景（超过 24 种颜色）的那一刻算「图出现了」。
- 切换：给窗口发一个 → 键（只发给这个窗口，不动别的程序），到那块像素发生变化为止。每次按键之间等 350 ms，开始按之前先等 1.5 秒让程序预读。
- 读的是窗口管理器合成的内容，所以窗口不必在最前面。

```powershell
go build -o bin\startbench.exe .\tools\startbench
bin\startbench.exe -n 7 -keys 6 build\windows-amd64\MyImages.exe D:\Pictures\a.jpg --ephemeral
bin\startbench.exe -n 7 -keys 6 "$env:LOCALAPPDATA\Microsoft\WindowsApps\ImageGlass.exe" D:\Pictures\a.jpg
```

这种测法的局限：中间那块如果本来就接近单色（比如截图），会判断不出来；`PrintWindow` 本身要几毫秒，所以 25 ms 这个量级的数字有几毫秒的误差；只测了这一台机器、这两类图片。内存用 `Get-Process` 读，脚本没有入库。

`myimages --bench <图片>` 是程序自己测的：从进程开始到第一张图的那一帧，以及连续切 40 张每张用的时间（这台机器上 9 ms 左右），不含系统显示窗口的时间。

## 解码器

`tools/decbench` 单独测解码（`-via wic` / `-via go` 只用一种，`-max N` 按 N 像素的方框缩小解码）。同一批文件，毫秒：

| 文件 | WIC 全尺寸 | Go 全尺寸 | WIC 缩到 1600 | Go 缩到 1600 |
|---|---:|---:|---:|---:|
| JPEG 4896×6528 | 200 | 284 | **52** | 246 |
| PNG 2448×3264（照片） | 109 | 185 | 108 | 206 |
| PNG 3413×3520（截图） | 87 | 107 | 81 | 135 |
| WebP 2448×3264 | 160 | 190 | 158 | 207 |
| TIFF LZW 2448×3264 | 123 | 143 | 122 | 166 |
| TIFF 未压缩 | 64 | 23 | 60 | 46 |
| BMP | 41 | 20 | 38 | 48 |

「Go」是标准库和 golang.org/x/image。WIC 的 PNG 不算快（每秒约 1 亿像素，单线程），但比 Go 标准库的快一倍左右，所以 PNG 仍然走 WIC；只有未压缩的 TIFF 和 BMP 是 Go 的更快，差的是十几毫秒，没有为它们另外分流。JPEG 缩小解码快四倍，是因为解码器自己按 1/2、1/4、1/8 解（见 design.md）。
